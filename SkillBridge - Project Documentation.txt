SkillBridge: Skill-to-Job Matching Platform
Technical Architecture & Project Specification Document
1. Project Overview & Executive Summary
1.1 Problem Statement
Traditional hiring platforms and job boards rely on keyword-heavy resume screening, creating significant friction between candidates and employers. Candidates often lack transparent feedback regarding why their profiles were rejected or what technical skills they lack for desired roles. Conversely, recruiters are overwhelmed by unqualified applicants and must manually vet resumes without an objective measure of skill alignment.
1.2 Proposed Solution
SkillBridge is a modern, skill-first recruitment and job-matching platform designed to match candidates to relevant positions based on verified technical competencies rather than static resumes.


Key outcomes delivered by SkillBridge:


* Objective Match Scoring: Generates a deterministic match percentage for every job-candidate pairing based on required and preferred competencies.
* Skill Gap Analysis: Highlights exact missing skills for a job posting and offers direct upskilling guidance.
* Streamlined Recruiter Pipelines: Automatically ranks applicants by compatibility, reducing time-to-hire.
1.3 Target Personas
* Job Seekers / Candidates: Students, career switchers, and professionals seeking roles aligned with their specific technical skill sets.
* Employers / Recruiters: Companies and hiring managers looking to define structured skill criteria and access pre-ranked applicant pools.
* Platform Administrators: Oversee system health, standardize the skill taxonomy, and monitor recruitment analytics.
2. Technology Stack & Architectural Decision
2.1 Architecture Model
The system follows a decoupled Client-Server RESTful Architecture:


* Frontend Client: Lightweight, responsive Single-Page Interface built with vanilla web standards (HTML5, CSS3, ES6+ JavaScript) using native Fetch API.
* Backend Service: High-performance Python backend powered by FastAPI, leveraging Pydantic for request/response validation and Uvicorn as the ASGI server.
* Database & Identity: Supabase (PostgreSQL), providing relational integrity, Row Level Security (RLS), Supabase Auth for JWT session management, and Supabase Storage for assets.

4. Database Architecture & Data Models
4.1 Relational Schema Specification
1. profiles: Stores user profile data linked directly to Supabase Auth.
   * id (UUID, Primary Key, Foreign Key to auth.users)
   * email (TEXT, Unique, Not Null)
   * full_name (TEXT, Not Null)
   * role (TEXT, Check: 'seeker', 'recruiter', 'admin')
   * bio (TEXT)
   * headline (TEXT)
   * location (TEXT)
   * resume_url (TEXT)
   * created_at (TIMESTAMPTZ)
2. skills: Centralized standardized taxonomy of skills.
   * id (UUID, Primary Key)
   * name (TEXT, Unique, Not Null)
   * category (TEXT, Not Null) -- e.g., 'Languages', 'Frameworks', 'Databases', 'DevOps'
3. candidate_skills: Association table for candidate proficiencies.
   * candidate_id (UUID, Foreign Key to profiles.id)
   * skill_id (UUID, Foreign Key to skills.id)
   * proficiency_level (TEXT, Check: 'beginner', 'intermediate', 'advanced', 'expert')
   * years_experience (NUMERIC(3, 1))
   * Primary Key: (candidate_id, skill_id)
4. jobs: Employer job postings.
   * id (UUID, Primary Key)
   * recruiter_id (UUID, Foreign Key to profiles.id)
   * title (TEXT, Not Null)
   * company_name (TEXT, Not Null)
   * description (TEXT, Not Null)
   * location (TEXT, Not Null)
   * employment_type (TEXT, Check: 'full-time', 'part-time', 'internship', 'contract')
   * is_active (BOOLEAN, Default: true)
   * created_at (TIMESTAMPTZ)
5. job_skills: Skill requirements defined for each job listing.
   * job_id (UUID, Foreign Key to jobs.id)
   * skill_id (UUID, Foreign Key to skills.id)
   * is_required (BOOLEAN, Default: true) -- true for mandatory, false for preferred
   * weight (NUMERIC(3, 2), Default: 1.00) -- importance multiplier (0.5 to 2.0)
   * Primary Key: (job_id, skill_id)
6. applications: Job applications with computed match snapshot.
   * id (UUID, Primary Key)
   * job_id (UUID, Foreign Key to jobs.id)
   * candidate_id (UUID, Foreign Key to profiles.id)
   * match_score (NUMERIC(5, 2)) -- recorded compatibility percentage
   * status (TEXT, Check: 'applied', 'reviewing', 'shortlisted', 'rejected')
   * created_at (TIMESTAMPTZ)
   * Unique Constraint: (job_id, candidate_id)
5. Skill-to-Job Matching Engine & Algorithm
5.1 Algorithmic Formulation
The platform uses a weighted dual-tier scoring algorithm that evaluates mandatory requirements separately from optional/preferred enhancements:


$$\text{Match Score (%)} = \left[ \left( \text{Weight_Req} \times \frac{\sum \text{Matched Required Weights}}{\sum \text{Total Required Weights}} \right) + \left( \text{Weight_Pref} \times \frac{\sum \text{Matched Preferred Weights}}{\sum \text{Total Preferred Weights}} \right) \right] \times 100$$


Default Parameters:


* Weight_Req = 0.75 (Mandatory skills contribute 75% of total score)
* Weight_Pref = 0.25 (Preferred skills contribute 25% of total score)
* If a job specifies no preferred skills, Weight_Req is set to 1.00.
5.2 Skill Gap Analysis Logic
For any candidate-job evaluation, the engine categorizes skills into three buckets:


* Matched Skills: Skills possessed by candidate matching job requirements (rendered green).
* Critical Skill Gaps: Required skills not found in candidate profile (rendered red with learning recommendations).
* Bonus Competencies: Preferred skills possessed by candidate (rendered blue).

* Interactive Elements: Responsive grid layouts, pill tags for skills, radial or bar progress indicators for match percentages.
6.2 Key Workflows
1. Candidate Journey:
Registration $\rightarrow$ Skill Selection & Proficiency Rating $\rightarrow$ Job Feed (Ranked by Match %) $\rightarrow$ Job Detail View $\rightarrow$ Skill Gap Breakdown Review $\rightarrow$ 1-Click Application.
2. Recruiter Journey:
Registration $\rightarrow$ Post New Job $\rightarrow$ Tag Mandatory & Preferred Skills with Weights $\rightarrow$ View Ranked Pipeline Dashboard $\rightarrow$ Filter Candidates by Threshold (e.g., $\ge$ 80%) $\rightarrow$ Update Application Status (Shortlist/Reject).

	8. Implementation Roadmap
   1. Phase 1 - Database & Project Setup:
Initialize Supabase instance, execute schema DDL, configure Row Level Security rules, and load initial skills taxonomy.
   2. Phase 2 - Backend Authentication & CRUD:
Set up FastAPI project with Pydantic models, Supabase Auth verification, profile endpoints, and job posting CRUD.
   3. Phase 3 - Matching Engine & Gap Analyzer:
Implement mathematical scoring service, unit test edge cases (zero skills, full match, partial match), and build gap analysis payload.
   4. Phase 4 - Frontend Development:
Build responsive HTML5/CSS3 templates, write modular vanilla JS controllers, integrate API client with local JWT storage, and build real-time match meters.
   5. Phase 5 - Verification, Testing & Deployment:
End-to-end integration testing, secure environment configuration, backend hosting (Render / Railway), and frontend hosting.
